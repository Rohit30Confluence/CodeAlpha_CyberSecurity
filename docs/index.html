The work

Four security problems. One lab.

Each section below shows what was built, how it behaves, and what evidence exists in the repository.

TASK 01

Network Sniffer

Python / Scapy

Packet metadata is summarized into a compact, readable view: source, destination, protocol, ports, timestamp and length. Live capture is bounded and opt-in.

# representative output
TCP  192.168.1.10:51524 → 93.184.216.34:443  len=74
DNS  192.168.1.10:52741 → 192.168.1.1:53    len=86
ICMP  192.168.1.1 → 192.168.1.10        len=98
Implementation focus: protocol visibility without dumping packet payloads.
TASK 02

Phishing Awareness

Interactive training

Scenarios cover lookalike domains, QR links, MFA fatigue, impersonation, malicious updates and safe reporting. The point is decision-making, not memorising definitions.

Quick check: A message says your account will close in 10 minutes and asks you to approve an unexpected MFA prompt. What do you do?
Training module: 10 scenarios with scoring and explanations.
TASK 03

Secure Coding Review

Python AST

A focused static reviewer walks Python syntax trees and flags selected high-risk calls. Findings include severity, location, explanation and remediation guidance in the report.

HIGH eval(user_input)
HIGH exec(source)
HIGH pickle.loads(data)
HIGH subprocess.run(cmd, shell=True)
Scope is intentionally narrow; it is not presented as a complete secure-code audit.
TASK 04

Network IDS Lab

Suricata 7

A capability-restricted Suricata container loads local rules and inspects a deterministic offline PCAP. The lab produces an actual alert and EVE JSON evidence.

Evidence chain: generated PCAP → Suricata replay → rule match → alert output.

Defensive by design

Capture is bounded, payloads are omitted from the sniffer display, and the IDS demonstration uses an offline lab rather than touching production traffic.

Reproducible

The Suricata exercise uses deterministic PCAP generation and pinned container configuration so the alert path can be demonstrated consistently.

Honest scope

This is an educational security lab, not a production SIEM, endpoint agent, complete SAST platform or enterprise IDS deployment.

1 — Build the visibility layer
Summarize packet metadata and keep live capture bounded.
2 — Add human-factor security
Turn phishing indicators into decisions a learner can practice.
3 — Inspect application code
Use AST traversal to identify a selected set of dangerous Python constructs.
4 — Validate detection
Generate known traffic, replay it through Suricata and verify the resulting alert.

Engineering notes

What I would improve next.

This is not a list of assignment instructions. It is the engineering direction for turning the lab into a stronger security portfolio.

Packet analytics

Add protocol statistics, flow grouping and exportable summaries while keeping capture privacy-conscious.

Detection quality

Expand IDS rules with better thresholds, rule metadata and structured alert triage.

Code review depth

Add additional secure-coding checks and eventually data-flow/dependency analysis rather than claiming completeness now.

Security operations

Connect alerts to a small local dashboard and introduce severity-based triage and investigation workflows.

Professional direction

The next version should demonstrate not just that a security tool can detect something, but that an analyst can explain the signal, validate it, assess the risk and recommend a defensible response.

Portfolio principle

Keep the implementation public, the evidence reproducible and the limitations explicit. A smaller system that can be demonstrated end-to-end is more credible than a large list of unsupported features.
